## 1 目标

建立一个原生 Windows 下可独立启动、可测试、依赖隔离的 FastAPI 后端起点。服务要诚实区分“进程可访问”和“知识问答未配置”。不等待校园语料，也不编造问答效果。

架构：单 Python 应用、app factory、独立健康路由和小型测试集合。当前没有数据库、模型、索引或队列。无需搭建前端、登录、RAG、语音、Agent 或容器。

## 4 接口契约

### GET /api/v1/health/live

HTTP 200，JSON 必须包含 status="ok"、service="campus-assistant-backend"、version="0.1.0"。只说明 API 进程可用，不依赖网络、数据库、磁盘扫描或外部服务。

### GET /api/v1/health/ready

本阶段固定为 HTTP 503，JSON 包含 status="not_ready"、code="KNOWLEDGE_BASE_NOT_CONFIGURED"、message="知识库尚未配置"、retryable=false。这里明确表示“知识问答能力未就绪”，不是启动失败。将来配置知识库后再按真实状态扩展，不设置一个环境变量就假装就绪。

此接口作为未来业务就绪检查；当前 README 中说明不能把它用作 T002 进程存活判断。OpenAPI 需明确声明 503 响应模型，文档不显示成只可能成功。

### 请求追踪

每个响应包含服务端生成的 X-Request-ID，可用 UUID；健康接口 JSON 同时携带 request_id 且与响应头一致。请求传入同名头也不直接信任或回显；本单统一生成新值即可，不增加复杂追踪框架。未知路径 404 响应也带响应头。不要回传机器路径、环境变量、密钥或完整异常堆栈。

默认 FastAPI 404 正文可保留，不为本单扩展一套全局错误框架。不得添加返回假答案的 /chat 接口或伪造连接正常的依赖状态。

## 6 必须验证的行为

1. live 返回 200 和约定字段，即使没有密钥、语料、数据库也可成功。
2. ready 返回 503、约定业务码和中文提示，retryable=false；不能错误返回 200。
3. 两个端点的 request_id 均为有效 UUID，与 X-Request-ID 一致；连续两次请求 ID 不同。
4. 客户端提供 X-Request-ID 时不会原样被服务信任或回显。
5. 未知路径返回 404 且有追踪头，不返回伪造的正常结果。
6. OpenAPI 包含两个健康端点，ready 明确包含 503 响应。
7. create_app() 可多次实例化，基本测试无外部网络、真实政策或 API key 依赖。

允许将这些行为合并成少量有意义测试，不以测试数量为目标。外部 HTTP 冒烟需分别记录 live 200 和 ready 503，并正确处理后者；503 是本阶段预期契约，不是测试失败。

## 7 复现命令目标

最终 README 应提供经过实际执行的 PowerShell 命令。约定在 backend 目录内使用：

```powershell
& .\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
& .\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
& .\.venv\Scripts\python.exe -m pip check
& .\.venv\Scripts\python.exe -m pytest -q
& .\.venv\Scripts\python.exe -m uvicorn campus_assistant.main:app --host 127.0.0.1 --port 8000
```

若采用上述无构建隔离安装，应将所需构建后端依赖包含在锁文件中并验证全新环境安装。不要交付看似完整却缺构建依赖的步骤。
