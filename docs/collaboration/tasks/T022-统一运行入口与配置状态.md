# T022 统一运行入口与配置状态

日期：2026-09-27；task_revision=v1。Astra发布，MiMo v2.6 Pro执行；前置T021-R1通过。

## 目标

将已验收能力整合到一个可复现的正常运行入口：指定语料包，按需开启已有本地向量模型、ASR、生成器及匹配当前语料的事项配置；首页如实说明哪些功能可用。既有demo-campus保留作明确模拟演示。本轮不新增算法、框架、数据库或Agent，也不发真实DeepSeek请求。

## 范围

1. 扩展serve-corpus.py或提供清晰替代入口（优先复用，避免再造一串脚本）。支持manifest/corpus-root、可选embedding-model-dir、asr-model-dir、procedures配置、self-check配置和显式生成器开关；模型目录仅本地，不自动下载。所有选项默认关闭，除指定语料外不隐式装入example、mock或旧演示配置。生成器复用现有DeepSeek适配器与环境变量密钥，不在CLI、配置JSON、状态响应、日志中出现密钥；启动不探测模型服务。
2. 明确配置优先级，提供不含密钥的配置示例和PowerShell启动命令，参数路径含空格可直接复制运行。显式请求某项功能但缺关键配置时，清楚说明失败或降级，不静默当作已成功启用。区分“已配置”与“已验证连接/模型加载”，不得仅因对象存在就声称服务可用。语料失败/部分成功仍沿用现有可见错误信息。
3. 增加聚合能力状态或由首页调用现有状态接口：首页显示语料成功数/错误、真实/合成/混合资料标记、检索模式、生成器身份及配置状态、ASR状态、办事模板/自查规则是否配置、是否有可比较版本。声明来源为当前服务状态，不硬编码全部合成或mock。未配置功能卡片保留明确解释，不能诱导用户认为真实政策事项已有完整模板。
4. 正常首页使用中性校园助手名称，合成演示问题只在明确demo场景出现。各页相关状态文字与实际语料一致；不重做UI视觉或前端框架。生成器启用后，只有用户明确点击生成才发请求；启动、状态刷新、摘录均零生成请求。识别文本确认后仍手动提问。
5. 核对现有依赖声明与安装说明能表达最小运行、检索增强、ASR等可选组合；不为了整合全量升级已装依赖。说明现有两种用途：统一离线demo（mock明确）与指定语料的正常运行。旧脚本如保留，README只给一个推荐正常入口。真实语料路径仍需用户提供，不造真实库。
6. 顺手处理T021-R1：登记输出命令的PowerShell路径引用；is_synthetic只接受JSON布尔值，不做bool强转；以API evidence跨度对照解析块替换自证式测试。改动聚焦，不延伸元数据平台。

## 验证

用现有合成语料验证正常入口的配置组合，但报告明确测试资料性质：最小配置=BM25/摘录；显式本地embedding目录后可用三模式（现有模型只加载一次，选一个查询即可，不跑旧评测）；ASR配置状态正确；模板/规则仅显式注入；未配置不偷偷启用。生成器通过注入计数桩或loopback验证启动/状态/摘录零调用及显式生成可达，不使用真实密钥或发送外部请求。

测试应围绕装配逻辑与状态真实性，不重测底层解析、ASR识别质量、全部检索算法。若依赖声明变化运行pip check。浏览器主路径：正常首页→看状态→搜索/摘录→未配置功能提示；无工具则交Astra补验。保留现有用户本机历史和待办，不清空用户存储。
