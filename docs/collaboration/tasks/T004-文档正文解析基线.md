## 目标

把已登记且校验通过的 TXT、DOCX 文件转换为有来源和位置的正文块，为后续引用展示与检索提供输入。此阶段不生成答案、不计算向量、不切成检索 chunk；原始正文块与之后的检索片段分开定义，防止丢失溯源信息。

不等待真实校园语料，继续使用明确标注的合成示例。PDF、扫描件 OCR、表格复杂结构恢复和前端上传留待后续任务；本单不承诺支持这些格式。

## 输入、输出与命令

复用 T003 manifest 和 corpus-root，不复制一套不一致的校验规则。先完整调用语料校验；任何校验错误都不解析正文，返回原有错误。校验成功后按清单顺序解析。

提供 CLI，例如：

```powershell
& .\.venv\Scripts\python.exe -m campus_assistant.corpus.parse --manifest .\examples\parse-corpus\manifest.json --corpus-root .\examples\parse-corpus
```

stdout 输出唯一 UTF-8 JSON 对象（作为程序间数据），不混日志。结构：schema_version="1.0"、valid（全部文档解析成功）、document_count（结构合法登记条目数，沿用 T003）、documents（成功解析的文档结果数组）、errors（错误数组）。命令默认不写磁盘；用户可自行重定向到文件，README 给出 Windows 方法。退出码 0=全部成功，1=输入/校验/解析失败，2=参数用法错误。

每个成功结果包含 document_id、完整 metadata（原登记信息，允许既有模型的规范化）、parser_version="1.0"、blocks。每个 block 至少含 block_id、ordinal、kind、text、locator。block_id 在相同文档 ID、源文件哈希、解析器版本和定位下确定性生成；不得每次随机 UUID。不同文档 ID 或内容版本不能误用同一 ID。ordinal 从 1 连续计数，仅针对输出的非空块。

locator 不伪造页码：TXT 用 type="lines"、line_start、line_end（原始文本 1-based 行号）；DOCX 用 type="paragraph"、paragraph_index（文档 body 顶层段落序号，空段也占序号）或 type="table_row"、table_index、row_index（各从 1 开始）。不返回机器绝对路径。

### TXT

支持 UTF-8（允许 BOM），统一处理 CRLF/LF。按空白行分段，保留段内换行与数字，不把日期或政策条款重新改写。每段记录原始起止行号；空白文件报 EMPTY_DOCUMENT，不作为成功。其他编码报 DOCUMENT_PARSE_ERROR，不猜测编码。

### DOCX

保留 body 中段落与表格的原始交错顺序，不可先输出所有段落再输出所有表格。非空段落输出 kind="paragraph"；表格按非空行输出 kind="table_row"，text 以制表符连接单元格文本，同时保存 cells 字符串数组，避免后续丢失列关系。普通表格即可；遇到嵌套表格、合并单元格、图片、页眉页脚等本单未保证的内容，在每个成功结果的 warnings 数组中说明提取限制，不声称完整保真。不得执行宏、访问外部关系链接或依赖安装 Microsoft Word。

损坏 DOCX、空文档、未支持扩展名均应明确失败，错误码至少有 DOCUMENT_PARSE_ERROR、EMPTY_DOCUMENT、UNSUPPORTED_FORMAT；沿用 code/document_id/field/message 的中文错误结构。结构和文件校验成功后，一个文档解析失败不妨碍收集其他文档的结果；valid=false 明确表示批次未全部成功，失败文档不输出伪正文。

## 示例与测试

建立 examples/parse-corpus/：至少一个含中文多段 TXT 和一个段落—表格—段落 DOCX，全为合成数据，附 manifest 与小型确定性生成脚本。脚本仅用于测试夹具，不写用户文件。用 README 解释如何查看正文块和定位，不把合成资料当四川农业大学政策。

先写有效测试并保存真实失败记录，再实现。覆盖：TXT 中文、BOM、CRLF、空行定位；DOCX 交错顺序、普通表格行列及空段位置；空文件、损坏文档、未支持格式、哈希不符时解析不执行；批次部分失败；重复运行 ID 稳定、内容或登记 ID 改变后 ID 不冲突；不修改源文件；无网络访问。每个负例从有效基线只破坏目标条件，断言准确错误码与定位。使用 subprocess 验证实际 CLI、UTF-8 JSON 和退出码。

运行全量回归及 pip check，独立环境按更新锁文件安装后复测。不要只记录测试数量；至少保存一个合成示例 CLI 成功输出和一个真实失败输出，说明定位如何回查原文。没有语料或链接创建权限不是伪造测试结果的理由。
