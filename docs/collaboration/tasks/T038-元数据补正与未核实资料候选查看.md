## 2. 独立只读候选API

新增`POST /api/v1/search/candidates`，复用SearchRequest的query/mode/top_k/filters/document_id规范及未知ID 422，新增`uncertainty_dimensions`数组仅接受`date`、`student_type`（可单项或两项，无选择拒绝422）。仅显式请求执行，不在status/startup/普通search/ask调用。

示例：
```json
{"query":"学籍基本信息有误去哪里办理？","mode":"bm25","top_k":5,"filters":{"student_type":"本科"},"document_id":null,"uncertainty_dimensions":["student_type"]}
```

- [ ] 候选文档必须在原请求至少一项已选择维度上实际未知：date对应effective_from=null且as_of_date非空，student_type对应scope.student_type空且请求student_type非空。没有相关筛选的维度不能作为放宽依据；请求只选无相关筛选维度时422中文提示。无实际候选时返回空，不找全库补齐。
- [ ] 每个文档独立检查全部条件：已知scope不匹配、未选放宽维度的未知scope、已知尚未生效/已失效均排除；campus/admission_year严格保留。日期开始未知但已有effective_to早于查询日也必须排除。不能直接挑原excluded_reason=scope_unknown的文档——该优先级会掩盖另一个已知冲突。未知date+未知student_type同时存在时必须两项均由用户选中才准入。
- [ ] 单文件document_id仍求交；不回退其他文件。候选集合排除严格已准入集合，先候选准入后各路TopK，共用既有索引/查询编码/排名，不重建文档索引。
- [ ] 响应含提交快照query/mode/filters/document_id、请求的uncertainty_dimensions、candidate_summary（文档口径与实际候选数）、hits。每hit附该文档真实unknown_dimensions/说明；原文/locator/preview_url服务器映射，按现有format_hit保持逐字引用。恒标“未通过所选日期或学生类型条件核实，仅供原文核对，不作为已确认适用的答案依据”。
- [ ] 严格search/ask的hits/filter_summary/source_selection保持原行为；候选不进入ask evidence包、生成messages、Agent工具结果、事项推荐或保存模板。候选接口只检索，绝不调用AnswerProvider/Planner/ASR。
