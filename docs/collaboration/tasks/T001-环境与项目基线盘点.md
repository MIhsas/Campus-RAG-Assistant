本任务不要求确定学校名称，也不要求现在搜集本校资料。资料缺失是需要记录的事实，不是让你虚构样例政策或停止所有盘点的理由。

## 3 写入范围和交付文件

仅允许创建、修改 `docs/collaboration/submissions/T001/` 下的文件：

- `report.md`：环境、项目、数据和阻塞项的综合报告。

不修改 step1、step2_code、step3_、方案、CLAUDE.md、任务书和状态表。不初始化 Git 仓库、不提交/推送、不下载安装依赖、不启用 WSL/Docker、不启动长期服务、不调用收费 API。只创建上述文档，无需测试框架或实现脚本。

## 4 执行步骤

- [ ] 确认当前目录确为 `F:\Collage Paper`。检查项目文件列表及已有修改。若存在 Git，运行只读状态检查；若不是 Git 仓库，如实记录，不初始化。
- [ ] 读取必读文件，以简短段落复述已确认方案：Windows 主机、自建 RAG、RAGFlow 参考、P1 学生功能、Agent 可替换且固定流程可用。列出仍属建议而非已确认的选择。
- [ ] 检查 Windows 版本、系统架构、CPU 型号、物理内存和 F 盘可用空间。仅记录技术字段，不收集用户名、序列号、机器 UUID 或网络配置。可用 Get-CimInstance 指定字段；失败时记录原因，不提权。
- [ ] 检查 Python、Node.js、Git、Docker、WSL 和可选 NVIDIA 工具是否可访问。先用 Get-Command 定位，再对存在的命令运行版本/只读状态检查；不要运行可能触发下载安装的命令。Python 只调用明确存在的解释器，不触发商店安装别名。
- [ ] Python 检查版本、解释器路径、venv/pip 可用性；不打印全部已装包和环境变量。Node/Git 检查版本。Docker 仅检查版本和现有服务状态，不启动守护进程。WSL 仅检查现有状态和发行版，不安装或更新。无 NVIDIA 工具只表示未通过该工具核查 GPU，不等于没有 GPU。
- [ ] 对权限失败、命令不存在、服务未运行、未检测到配置分别标注。原生 Windows 与 WSL2 路线做可行性对照，但不能把 WSL2 的存在当成用户同意使用。
- [ ] 盘点项目资料：step1 文件名、类型、字节数与 SHA-256；step2_code 和 step3_ 是否存在实际文件；docs 已有方案。不要扫描整个用户目录，不读取 `.env`、Claude Code 服务配置或密钥文件。
- [ ] 明确原开题报告属于项目设计资料，不属于校园政策知识库。如果没有学校手册或通知，报告“本次限定目录内未发现”，不要扩大为电脑上完全不存在。
- [ ] 给出下一单建议及前置条件：有可用 Python 时可以准备项目隔离环境方案；本校来源未明确时需要用户提供学校或权威材料。只建议，不执行下一单。
- [ ] 完成交付清单，核对 JSON 可解析、路径一致和命令证据真实，提交后停止。

命令仅是检查手段，可用等价的原生 PowerShell 只读命令。不要为补齐某字段尝试提权、全盘搜索或远程安装。使用工作目录内的相对路径记录文件，解释器路径仅作环境复现；输出中出现无关个人字段应删除。

## 5 inventory.json 约定

顶层字段：task_id、task_revision、checked_at、workspace、system、tools、project_files、knowledge_corpus、open_questions。

- task_id 为 T001；task_revision 为 v1；checked_at 用真实执行时间和时区。
- system 包含 os、architecture、cpu、memory_gib、workspace_disk_free_gib。无法获取的值使用 null，并在 report.md 说明。
- tools 为数组，每项 name、status、version、executable、evidence_id。status 只使用 available、not_found、not_running、unknown。命令存在但服务未运行时不能标 not_found。
- project_files 为数组，每项 path、bytes、sha256、category。资料文件填真实哈希；目录不伪装成文件，不要求为文件夹生成哈希。
- knowledge_corpus 包含 status（found 或 not_found_in_scoped_scan）、scope 和 paths。
- open_questions 为仍需用户/验收者决定的问题数组，不填写猜测答案。

## 6 verification.md 约定

每项检查有证据编号 V01、V02 等，记录工作目录、完整检查命令、成功/失败标志或退出码、相关输出、解释。失败也保留。PowerShell cmdlet 无独立进程退出码时记录异常和执行成功标志，不编造进程退出码。

至少提供：工作区盘点、操作系统与资源、工具检查、报告文件哈希、最终 JSON 解析检查。若命令输出包含私密字段，只保留技术相关字段并标记已脱敏；不附原始私密日志。

## 7 submission.json 约定

包含 task_id=T001、task_revision=v1、submission_revision=1、status、summary、files、checks、blockers。status 为 ready_for_review、partial 或 blocked。

files 列出四个交付文件的项目相对路径；checks 列出验证项目、结果和 evidence_id；blockers 是事实阻塞数组。缺学校名可以列为后续语料任务前置条件，但只要盘点完成，本任务可以 ready_for_review。不要填写验收通过或下一单已启动。
