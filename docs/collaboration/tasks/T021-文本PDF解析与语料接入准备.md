# T021 文本PDF解析与语料接入准备

日期：2026-09-27；task_revision=v1。Astra发布，MiMo v2.6 Pro执行；前置T020-R2通过。

## 目标

为用户随后提供的学校公开文档补齐文本PDF入口，以及可复查的本地语料登记操作。现有前台功能继续复用；本轮不爬取学校网站、不虚构真实语料、不接OCR或付费模型、不新增数据库/管理员平台。

## 实施范围

1. 使用 pypdf 在现有 corpus validate/parse 管线增加文本PDF支持。允许项目局部依赖，记录实际版本并更新依赖声明。原文件保留；逐页提取文本，块有一基页码及页内稳定定位。明确空白/换行规范化规则，不能用LLM补正文；保留可追踪的提取文本供人工核对。PDF引用跨度相对于该提取块逐字一致，不宣称与视觉排版完全等价。
2. 保持既有TXT/DOCX块ID、模板与规则引用兼容。注意当前PARSER_VERSION参与block_id计算，不可只为PDF升级全局版本导致所有旧引用失效；为PDF独立版本/定位规则，或采取兼容设计并解释。
3. 图片型/无可提取文本页记录“未提取到文本，可能需要OCR/人工核对”；不能断言所有空白页都是扫描件。全篇无文本不进索引、不算解析成功。混合文档有明确部分提取与缺失页提示，不悄悄把整篇标完整；为控制范围可以先整篇阻止入索引并提示补资料，不要求本轮做复杂部分索引。加密或损坏文档明确失败，不解密绕过，不实现OCR。复杂表格/多栏仅声明提取限制，不声称结构识别。
4. 串通现有 preview→search→ask extractive：PDF块显示页码与原文出处、来源元数据，命中跳转到对应提取块。不必实现内嵌PDF阅读器或原文件下载接口。使用独立合成PDF演示语料，不混入旧parse/comparison语料，不改gold。
5. 提供本地语料登记辅助CLI：输入一个本地文件及现有manifest所需元数据，计算文件哈希，输出独立候选语料包（原文复制+manifest），然后复用校验/解析检查，给出可读结果及启动命令。只写指定的新输出目录，不覆盖已有库；缺必填元数据明确列出，不猜学校政策标题、发布日期、适用范围或现行状态。可先使用元数据JSON作为CLI输入，不另造表单系统。TXT/DOCX/PDF均复用此入口；不下载source_url，不修改用户输入原文件。
6. 真实资料尚未给出，提供简短接入说明：需要哪些原文和来源页面信息、未知字段如何按既有schema填写、如何区分synthetic与真实资料、怎样人工核对PDF抽取并确认再启动服务。正常资料库不得默认加载合成办事模板、自查规则或mock生成器。无需为未知字段扩展一整套审核系统。

## 验证与交付

准备独立可复现两页中文文本PDF，能核对数字、否定词、页码及搜索命中引用；以及一份无文本PDF用于明确不可用状态。用生成脚本或来源明确的合成夹具，记录生成方式，人工对照页面文字与提取块。相关测试覆盖多页提取/稳定ID、无文本和解析失败、PDF引用定位，以及旧TXT/DOCX ID与模板引用不变。登记CLI跑一次成功与缺元数据失败即可，不扩展无关安全矩阵。

运行受影响的解析/检索接口与模板聚焦回归；若只改preview，JS只检查对应语法/行为。不跑全量、embedding重编码、ASR或真实生成。依赖新增运行pip check。无浏览器能力提供可启动演示入口与步骤，等待Astra补验。

参考：pypdf官方文本提取说明 https://pypdf.readthedocs.io/en/stable/user/extract-text.html 。Astra本轮已核对：pypdf不进行OCR，PDF提取与阅读顺序/布局存在限制；实施时记录实际使用版本，不照抄未验证能力。
