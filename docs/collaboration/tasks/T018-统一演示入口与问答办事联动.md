# T018 统一演示入口与问答办事联动

日期：2026-09-27；task_revision=v1。Astra 发布，MiMo v2.6 Pro 执行。前置 T017-R2 通过。

## 目标

把已有问答、证据预览、办事清单、待办与版本对比接成同一个本地服务内的答辩演示。解决当前比较语料和办事语料需要不同演示入口的问题，增加从提问到办理的明确入口；复用既有业务，不重新开发已验收算法。

## 范围与步骤

1. 在 step2_code/backend/scripts 新建统一离线演示入口（如 demo-campus.py）。显式使用本地 mock provider，所有模拟回答带标记；不得读取真实生成器配置来自动调用 DeepSeek。将现有 parse-corpus 与 comparison-corpus 组合为独立演示语料目录/manifest，使用原文档 ID、原文件内容及哈希；可由脚本在项目 .cache 中构建，不修改两份原始夹具和 gold。模板仍绑定原 parse-corpus ID。ID 冲突时明确报错，不静默覆盖。避免重复维护两份内容手工漂移。
2. 提供统一 `/` 首页或 `/home`，作为五个功能入口：问答、证据搜索、办事与待办、版本对比、语料预览。显示合成演示和模拟生成状态，列出三条可点击演示问题；状态展示必须来自当前服务，不能写死“真实模型已连接”。从所有页面可回首页，不重建前端框架。
3. 在 ask 页增加“相关办事事项”卡片，支持缓考申请、成绩复核两个既有事项。使用显式关键词/事项映射，标注“相关事项入口”，不宣称 Agent 推理或用户符合条件。链接使用稳定 procedure_id，不依赖标题拼接；其他问题无匹配就不显示推荐。
4. 用户明确点击办事卡片后跳转 procedures 页，带入本次已提交的问题对应事项及筛选快照（query/filters 可用 URL 参数，注意编码；不传答案原文或密钥）。procedures 页面显式显示已带入条件，仍需用户点击生成草稿，禁止自动保存待办或自动调用模型。要等筛选选项加载后再恢复值；不存在的选项保留并提示，不能悄悄取消。
5. 若用户查看历史问答，办事入口采用该历史结果的筛选快照，并提示将按当前加载资料重新生成指南；不能取当前输入控件的另一组条件。更改控件后尚未再次提问，不得改写旧结果卡片携带的快照。页面原有重试/失败转摘录/历史行为保持。
6. 统一演示服务中能打开已保存待办、查询当前依据、打开同一个文档原文，也能比较独立比较组两版。组合语料会改变检索候选，示例问题若被比较语料干扰必须如实处理（例如演示清晰的筛选条件），不得伪造检索结果或覆盖旧评测预期。
7. 给出 Windows 单条启动命令和 5—8 分钟答辩演示脚本：首页→问答证据→相关事项→带条件草稿→保存并勾选→原文核对→版本对比→返回待办。标明每步是确定性功能、模拟生成还是 T014 历史真实服务证据，不把本轮 mock 说成 DeepSeek 实时回答。正常业务启动入口保持原样。

## 验证

只做聚焦回归：组合语料各文档哈希/ID不变且可解析；同一 app 上各路由可用、模板引用通过；问答结果快照→办事页条件一致；历史快照不取新控件值；跳转不自动发模型/保存请求；旧问答快照和失败转摘录保持。相关 JS/路由测试即可，不重跑 embedding、全量测试或旧评测。不得为追求测试数量增加矩阵。

有浏览器能力则跑一次跨页闭环；无能力则提供 Astra 可运行入口与逐步检查表，明确未实测。所有开发与验证仅本地，external_model_calls=0。任务不授权新增付费调用、不修改系统代理、不安装 WSL 或数据库。
