# T010 向量与混合检索闭环

发布：Astra。执行：Claude Code 中的 Mimo。日期：2026-09-21。task_revision=v1。前置：T009-R2 通过。

**目标：一次交付可运行的 BM25、向量、混合三种检索模式，让用户在搜索页切换，并能用同一题集比较结果。** 本单合并算法、接口、展示和评测适配，不再逐个小模块拆任务。还不生成自然语言答案。

## 方案与范围

采用本地 `BAAI/bge-small-zh-v1.5`，Sentence Transformers 在 Windows CPU 推理；归一化向量用 NumPy 精确点积排序。现有语料很小，本轮无需为了部署 FAISS 增加调试环节；保留检索类接口，后续规模需要时替换为 FAISS。原 BM25 与分块策略不改，混合采用 RRF。

官方依据（2026-09-21 核对）：[BGE 模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[SentenceTransformer 参数与 encode](https://www.sbert.net/docs/package_reference/sentence_transformer/model.html)。模型查询加 `为这个句子生成表示以用于检索相关文章：`，正文不加；用 normalize_embeddings=True，显式 CPU、float32，不启远程自定义代码。

只写 `step2_code/backend/`、`step2_code/README.md`、`docs/collaboration/submissions/T010/`。本单允许在项目 .venv 安装 sentence-transformers/numpy 及必要依赖，从官方 PyPI/PyTorch 来源安装、从官方 Hugging Face 模型仓库下载本模型到 backend/models/；缓存放 .cache，不修改全局 Python/系统配置。记录实际依赖锁与模型 revision。无需付费 API、账户登录、GPU、Docker/WSL。网络不可达时交付可完成部分及确切阻塞，禁止把伪向量当真实模型结果。

明确下载脚本与运行服务分开：服务只读取本地模型，未配置模型的普通应用仍能使用原 BM25；不能启动默认应用就下载权重。代码/报告不包含模型大文件。可增加 `scripts/download-embedding-model.py`，下载配置、分词器及一种必要权重格式，避免重复下载所有框架权重。

## 1. 检索器

建议新增 `retrieval/embedding.py`、`dense.py`、`hybrid.py`，必要时用小型 `service.py` 统一选择模式，不做无用途分层。

- Embedding：提供文档批量编码和查询编码，模型进程内只加载一次；维度从模型获取，不硬编码猜测。文档向量一次批量构建，查询时仅编码当前问题。保留实际最大 token 长度和截断说明；尤其超长表格如被截断须记录截断块数，不宣称全文均参与向量计算。
- Dense：复用同一批 chunk，保留完整 chunk 和 preview_url；归一化后点积按分数降序、chunk_id 升序稳定排序。本阶段仅返回 score>0 的候选，明确这是候选规则而不是相关性/可信度阈值，不用 0.5 等数值冒充答案可靠性。空白/无有效文本不生成占位命中。
- Hybrid：BM25 和 dense 各取前 20 个候选（不足取实际数量），按 chunk_id 合并。`rrf_score = Σ 1/(60+rank)`，排名从 1 开始，缺失一路贡献 0；同分按 chunk_id。记录每一路 rank/原分数、融合分，不能直接把 BM25 分数与余弦分数相加。
- 所有模式返回兼容现有 hit 的 rank/score/chunk/preview_url/matched_terms。dense 的 matched_terms=[]；hybrid 可附 BM25 词匹配，但不要伪造向量“关键词贡献”。可追加 bm25_rank/dense_rank/bm25_score/dense_score 等可空字段供 UI 解释。

## 2. 应用与可见功能

create_app 增加可选 `embedding_model_path`，保持现有参数和默认行为。配置模型时复用解析/分块快照并构建 dense；模型缺失或加载失败只让 dense/hybrid 不可用，不能破坏 BM25 和原文预览。status 增加 available_modes 与每种模式可用性/安全中文原因，模型名/版本可显示，不返回机器绝对路径。知识问答 health/ready 仍为 503。

POST `/api/v1/search` 新增 `mode: bm25|dense|hybrid`，省略为 bm25，原有客户端继续可用。选择不可用模式返回明确 503/RETRIEVER_UNAVAILABLE；不静默换成 BM25。成功响应带 mode，沿用原 query/top_k/证据字段。大块初始化工作只发生在应用创建阶段，查询不重建语料向量。

`/search` 增加“关键词 / 语义 / 混合”选择器，默认关键词。未启用模型的选项禁用并说明原因；结果标签绑定提交时的模式与问题，失败重试使用原参数（含模式）。分数分别标“关键词匹配分 / 语义相似度 / 融合排序分”，不称置信度。混合结果展开可看两路排名，保留来源与原文跳转。模式切换不自动冒充已经搜索完成，点击搜索才更新结果。

给出可复制的 PowerShell 启动方式。可让专用 demo 入口读取 `CAMPUS_EMBEDDING_MODEL_DIR` 路径并传给工厂；默认 main 不隐式读此配置。CPU 查询会变慢，保证加载状态可见，避免重复模型初始化；本轮不做复杂缓存、并发调度或登录系统。

## 3. 同一题集对比

复用 T009 的标注校验和指标，CLI 新增 `--mode bm25|dense|hybrid`、`--model-path`，默认 bm25。题集不因检索模式而重标、不为提高分数改 gold。先完成全部来源校验，再执行检索；普通 BM25 不依赖安装模型成功。

报告输出 mode、模型标识/revision（无模型为 null）、向量归一化/查询前缀、RRF 参数及原有数据指纹。保持同一批 chunk 的来源映射；保留真实指标精度，不对三种不同性质的 score 作数值比较。

在同一 8 题合成开发集运行三种模式，提交对比表及每题结果。另给 2—3 个真实运行的检索例子，说明排序差异和局限；不要求语义/混合必胜，不把合成分数称为真实学校准确率。模型未取得时不得声称三模式完成。
