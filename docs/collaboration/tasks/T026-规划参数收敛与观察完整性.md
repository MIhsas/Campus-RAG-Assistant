## 目标

根据 T025 真实记录，减少模型在固定条件上犯错的机会，同时避免把观察摘要的截断误当成完整信息。保留一次真实失败证据，不为获得 completed 放松执行判定。

## 范围

1. **规划专用声明**：模型看到的 search_policy 参数只保留必要的 query（及确有用途的可用 mode/top_k），不再要求/允许模型构造 filters；build_checklist_draft 使用用户已选事项，可不向模型暴露 procedure_id。执行层从用户快照注入固定条件及事项。保留现有业务层拒绝机制，模型额外传 filters/改事项时明确拒绝，不能静默忽略后执行。不要修改已有搜索/办理API的正常契约。最小实现即可，不引工具框架。
2. **清晰工具说明**：提示词提供一组正确 JSON call 示例，明确省略固定条件、事项；模式可用性依据本次上下文，默认 BM25。只向模型声明实际支持参数，避免共享 catalog 与新校验规则不一致。缺用户输入依旧 awaiting_input，不猜事项。
3. **观察完整性**：现有 pending_items 最多3项而真实草稿有4项，模型结束语遂称3项。摘要保留现有预算，增加总数、已列数和截断标记，让“列了3项”不等于“总共3项”；其他有界集合用同一必要原则，不发送整库。UI/报告不得拿模型 summary 覆盖工具完整结果。
4. **事实说明**：附加 T025 记录勘误（不覆盖 live-run.json）：第1轮拒绝、第2轮检索、第3轮才可能使用检索观察；区分事件证据、由代码推断的提示构造、实际捕获的出站请求。明确真实链路已打通但完整冒烟含拒绝，planner_live_verified 继续 false，不擅自升级。

允许修改 agent 工具声明/适配提示/观察构造及直接相关测试脚本说明、submissions/T026；如需调整 API 状态展示只做必要字段同步。不得改原始 live-run、语料/gold、模板、学校政策、完成判定和本轮HTTP预算。不安装依赖、不下载模型、不执行 live。
