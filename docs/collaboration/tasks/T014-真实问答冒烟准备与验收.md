目标：整理可审查的真实 DeepSeek 冒烟脚本和两道合成问题；用户确认调用授权后，完成最多两次官方请求及逐条引用人工核对。本文件区分已授权本地工作与尚未授权的外部调用，不能把发布任务理解为允许扣费。

## A. 立即执行的本地工作

允许修改 step2_code/backend/ 中相关脚本、少量测试及 README，以及 docs/collaboration/submissions/T014/。不重构检索、模型适配器或页面，不增加安全矩阵，不改旧 gold 或 Astra 文件。

修正 T013-R1 的四个记录问题：失败非零退出；完整独立保留 status、generation_meta、model/request_id/usage、finish_reason 和实际调用记录，答案预览才截短；输出字符参数限制为 1—2000（不能用它充当 token/费用限制）；区分 ask_requests 与 external_http_attempts，真实 HTTP 尝试计数不通过 /ask 条数推断。无重试，最多两次；首次技术失败立即停止。

用原 parse-corpus 选择两题，保持 mode=bm25、max_tokens=1500、每次实际证据字符不超过 6000：

- 可回答题：“缓考申请须由谁批准，之后还需要向哪个部门备案？”年级 2023。预期核对 TXT 第二条的所在学院批准、教务处备案。答案措辞不必完全一致。
- 材料不足题：“宿舍门禁时间是几点？”不设范围。当前语料没有该事实。检索若返回无关候选，生成器应说明不足；不得用模型常识回答。无候选时记录本地短路、真实 HTTP 次数为 0，不谎称验证了模型拒答。

脚本在 dry-run 先完成本地检索并输出审查摘要：官方目的地址、model、问题、条件、实际证据 ID/字符数、预计最多调用数、max_tokens。无密钥也能准备，密钥不打印。默认 dry-run 不能联网。

结构化结果与答案预览分开；如保留完整合成回答供核对，明确另存本地 JSON，不把预览截断误认为模型截断。报告不预填成功或模拟 usage。可用 loopback 测试验证一个成功和一个 HTTP 失败的记录/退出码，不需重跑 441 项全量、JS、依赖或 embedding 评测。

## B. 外部调用前提

仅在用户后续明确提供调用授权和本地密钥配置后执行 --live。建议向用户请求的具体范围：DeepSeek 官方 https://api.deepseek.com、model=deepseek-flash，以上合成资料，最多两次 HTTP 尝试、每次 max_tokens=1500、无重试。用户可另设费用上限；实际执行不得超出最新授权。

本任务发布时以上真实请求尚未授权。不读取 Claude Code 配置，不把密钥贴进聊天/报告。A 部分完成后若仍无授权，提交准备结果并停止等待；不要为了交付 ready_for_review 擅自调用。用户可在准备过程中明确追加授权，此时按其最新范围执行，无需再次确认相同事项。

## C. 获得授权后的核对

真实生成结果逐段核对：数字/部门/条件是否与原文一致、引用是否支持主张、材料不足时有无编造。答案不合格如实报告，不通过改 gold 或悄悄重试美化。两次冒烟仅证明链路与个别行为，不是校园准确率或可靠拒答指标。

不需要为核对再点页面生成一次而额外消费。保留实际 provider metadata、时间和调用次数；缺失值为 null。报告任何失败和费用/用量记录的局限。
