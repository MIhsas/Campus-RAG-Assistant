## 目标

把 T024 的文字冒烟计划变为可复现、可核对的单次 CLI 运行。沿用 T014 已有设计经验，避免依赖浏览器手点和手工拼接日志。只实现必要运行入口与审计，不另造 Agent 框架或扩展工具。

## A：本地准备（现在执行）

新增 `backend/scripts/live-smoke-planner.py`：默认 dry-run，无网络、不要求真实密钥。使用既有 parse-corpus 合成资料及 procedures 模板，固定一题“查找缓考依据并整理办理草稿”、proc-apply-defer、年级 2023。dry-run 展示配置计划、资料身份/合成标记、预算、预期检查项；不得用脚本规划结果冒充真实模型。实际 loopback 联调可独立测试，但不能静默成为 live 的降级分支。

`--live` 实现留待授权后执行：只运行一次 planner loop，≤4 次 HTTP、每次 max_tokens=300、零重试、现有单次 20s/总调度 30s；故障停止，不自动再跑一题。不启用答案生成器。复用真实执行层，不另写一套流程。若未达必要产物完成条件，原样记录 partial/stopped，不靠补工具凑成功。

首次请求前完成并输出实际配置校验：官方 `https://api.deepseek.com`、`deepseek-flash`、300；语料解析成功、非空且全部 is_synthetic=true；只接受本任务固定题目和本地模板。配置/资料不符合则非零退出且零请求。允许测试代码显式注入 loopback，但 CLI live 不得把任意环境地址当成获授权官方地址。密钥仅通过现有环境配置加载，不读/打印 .env 或完整环境，不写报告。

记录完整本次输入快照、语料/模板哈希、实际配置（不含密钥）、run 状态与 stop_reason、服务端结论、实际动作及观察摘要、实际工具结果/引用、每轮 provider 审计、真实 HTTP attempts。计数尽量在 HTTP 发送处观察，不能单凭 plan_rounds 推算；不可加入重试。缺少 usage/request_id 写 null，失败已获得的审计能保留则保留，不能伪造。仅保留合成资料相关内容，不记录 Authorization 或密钥。返回非 completed、技术失败或前置失败均非零；参数错误可用 argparse 2。默认 dry-run 成功为 0。

生成“逐条核对表”：是否实际搜索、草稿是否存在且事项/条件正确、引用是否与直接 service 相同、是否需人工核实、是否有失败/提前 finish、是否零自动保存。真实运行时按实际动作核对，不预写通过结论。

只做三类本地验证：正常 dry-run 零网络；loopback 完整链路且 attempts 与服务端接收数相同；提前结束/技术失败非零、保留部分证据。复用已有前置校验测试经验，不铺开重复安全矩阵。没有改 UI 不跑 JS，没有改共享核心不重跑全量/模型测试。可抽取很小的审计接口，改到哪里补哪里回归。

允许改动：scripts、新脚本的聚焦测试、必要最小规划审计支持、README 的运行说明、submissions/T025；不改语料/gold/产品模板/前端，不装依赖、不下载模型。
