## 1. 筛选语义

POST /api/v1/search 增加可选 filters 对象：campus、student_type、admission_year、as_of_date。前三者单值，日期 YYYY-MM-DD；未填字段不限制。响应回显规范化 filters，并说明各筛选计数的口径。

- 指定维度必须在文档 scope 对应数组中。空数组表示未知，不是适用所有人；该维度被筛选时排除未知，并报告排除原因计数。
- 日期筛选：已知 effective_from 且不晚于查询日；effective_to 已知时要求查询日不晚于该值，本任务采用两端包含区间。effective_to=null 表示无已标注截止，不证明永久有效；结果注明“未标注截止”。effective_from=null 时不能确认适用日期，排除并计数。published_at 不代替 effective_from。
- 所有已选条件 AND。未提供任何筛选时，保持 T010 的候选与排名行为。
- 不凭标题或 version_label 猜“最新版”，同一家族的多个匹配版本保留；不把筛选结果叫正式资格结论。

各模式使用同一文档准入集合。BM25 保持全库 IDF，不因选择条件重新编码或重建索引；在打分候选中先应用准入，再取 Top-K。Dense 同样先限制准入再取 Top-K；Hybrid 各路从准入集合各取前 20、重新从 1 排名后 RRF。不能先取全库 Top-5/20 再简单删项。无候选直接返回空结果，不回退到不符合条件的文档。保留稳定排序、preview_url、来源信息。

建议用轻量 filter 函数和检索器可选 allowed_document_ids 参数，不为此引入通用规则平台；空集合与未传集合要区分。

## 2. 前台可见闭环

在现有 /search 增加四项筛选及“清除条件”。校区、类型、年级选项从当前已解析语料提取并去重，提供“不限”；可由 status 扩展返回选项，无需用户档案系统。日期默认不限制，由用户输入。

提交后显示这次查询实际采用的条件和结果数量；控件随后被编辑不应改变已有结果的条件说明。失败重试沿用上次 mode/query/filters。结果保留原文跳转，展示匹配条件和日期信息；无结果区分“没有满足所选条件的资料”和“满足条件的资料中没有检索命中”，提供清除条件的操作。文本明确这是证据检索，不是政策答案或资格认证。

维持简单静态页面结构；不在本单迁移 Vue 或整站改版。允许增加少量样式以让筛选易用。

## 3. 合并收尾

完成 T010-R1 中列出的五项，不另开架构工程：

- 修复行为脚本 stub，覆盖新筛选及 mode/query/filters 的重试快照。保留旧的有意义断言。
- 服务仅接受实际本地模型目录，SentenceTransformer 显式 local_files_only=True；加载失败保留 BM25/预览并给中文原因。status 显示模型 ID，不显示本机路径。别通过全局离线设置代替代码约束。
- 保留模型 token 上限，统计正文编码发生截断的块数；结果和报告说明长块可能仅部分参与向量计算，原文和 chunk 不能被截短覆盖。模型 revision 从现有下载元数据核实，无法核实则 unknown。下载脚本后续只拉一种权重，不重下载现有模型来完成本任务。
- 给出三种评测的完整 CLI 命令和原始 JSON 输出。保持原 8 题 gold 不变；本轮默认无筛选的对比仍有可比性。无需在旧评测 schema 强塞筛选功能，新筛选用独立夹具/API 演示验证。
- 语义结果显示依据实际 hits，不以 BM25 分词是否为空替代；修正文案。
