# T034：重叠分块与完整证据覆盖的离线对照

task_revision=v1。前置T033通过。仅执行本任务，完成后停止；T035未发布。

## 目标

当前 `corpus/chunk.py` 将段落块按500字符连续硬切、无重叠；完整事实可能被边界切开。对真实T030 v1.3开发集做**一次固定方案**对照，检验增加重叠是否改善证据覆盖/排序。不是重新标注gold，也不以结果好看为目标。保留全部失败与回退；本轮不将实验方案变成默认产品行为。

## 实现与固定参数

1. 在既有 `corpus/chunk.py` 提供显式可选 `overlap_chars`，默认0与现有行为一致。只对paragraph的块内窗口应用；固定实验max_chars=500、overlap_chars=100、步长400，最后一块到块尾后终止，不额外产生冗余尾窗。table_row及解析block完全不变，不跨页拼块、不改原始文本、不新造来源。
2. 每个新chunk保留原document_id/block_id及真实块内[start,end)；text必须逐字等于原块切片。实验策略/参数有明确身份并参与新增chunk ID。默认0的旧ID、顺序、文本、字段语义和表格处理保持兼容；不要全局升级常量导致旧ID无谓变化。
3. 只通过独立实验脚本显式调用新选项，不扩展网页开关、服务默认参数、检索模型或评分公式。允许脚本直接复用现有索引/筛选/metrics，不能另写有利于新方案的评分。

## 实验设计（跑前冻结）

- 真实包sicau-rag-pilot-v1.1、T030 v1.3全部24题、原query/filters/gold不变；top_k=5，原BM25参数、BGE模型、RRF参数保持。**不加T031人工文件选择**，避免把两种变化混在一起。
- 在 `data/evaluations/sicau-rag-overlap-v1/` 保存跑前配置、题集/语料/关键实现/模型身份哈希。只比较baseline overlap0和candidate overlap100，不网格搜索、不看分数后调窗口/改题或删失分题。
- baseline可复用T030 v1.3存储排名，但须明确历史身份并核对输入一致；当前未改窗口路径的BM25排名24题做兼容检查即可，不要求重编码baseline。若不一致必须先解释，不能偷偷覆盖基线。
- candidate每个模式各跑一次；Dense/Hybrid共享同次候选编码与索引，候选文档只编码一次；本地已安装模型复用，不下载新模型。若编码资源受限如实记录，不擅自缩题集。
- 输出逐题与聚合R/H/M、分组、可答20题与不足4题分母分开；不足仍用空检索率，不能叫拒答率。原metrics允许多个命中区间共同覆盖事实，保持原义；新增重叠可能挤占top5，必须记录重复区间比例/同块命中和不改善案例。
- 至少对照一个实际边界事实与一个排序回退/不改善案例；若没有对应现象如实说明，不造案例。区别“候选中存在完整事实”“进入top5”“整题回答正确”，实验只评价前两者相关检索指标，不产生答案质量结论。
- 这是已见模型辅助开发集上的开发实验，非独立测试集或校园准确率。无收益也可交付通过；本轮只给采用/不采用建议，默认不切换。
