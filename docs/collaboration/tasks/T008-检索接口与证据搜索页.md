## 1. 工厂快照

保持 create_app(manifest_path=None, corpus_root=None) 现有成对配置约定。配置时已有 parse_manifest 一次，复用返回 documents 调用 chunk_documents(max_chars=500) 一次、BM25Index 一次；不得调用 chunk_manifest 造成重新解析。默认未配置不读取文件/不建索引。多 app 各自独立，重复 HTTP 请求不重建，不因查询而写磁盘。

新增检索快照状态：unconfigured、ready、partial、failed。就绪/部分成功沿用语料状态；全纯标点可为 ready 但 indexed=0，这是加载成功且没有有效词元。失败状态保留语料错误；构建异常转为 failed，记录安全中文 INDEX_BUILD_ERROR，不向客户端暴露绝对路径或 traceback。错误状态不影响原文预览；健康 live 保持正常，既有 `/api/v1/health/ready` 仍为知识问答未就绪 503，不能因为 BM25 可用就伪造问答 ready。

## 2. API

GET `/api/v1/search/status` 始终 200，明确 Pydantic 响应：status、document_count、parsed_count、chunk_count、indexed_chunk_count、synthetic_count（已解析文档中合成数）、errors、request_id。版本字段 retriever_version/tokenizer_version/chunker_version 及固定参数 max_chars=500/k1=1.5/b=0.75 一并返回。计数源自实际快照，indexed 为 T007 的有效数。

POST `/api/v1/search`，JSON `{ "query": "缓考申请", "top_k": 5 }`。query 必须严格字符串，长度 1—500、不能全空白；不自动改写，top_k 默认 5、严格整数 1—20，拒绝 bool/float/string。多余字段拒绝，不能接受文件路径/manifest/模型参数。无效输入 422（框架标准 validation detail 可保留），必须有 X-Request-ID。

正常 ready/partial 返回 200：query、query_tokens、status、chunk_count、indexed_chunk_count、hits、errors、request_id。hits 使用明确嵌套响应模型，复用 T007 字段 rank/score/chunk/preview_url/matched_terms，chunk 字段与 T006 一致，locator 可用已定义内部结构；不要只用顶层 dict 充当整个契约。request_id 与响应头一致。

未配置返回 503/CORPUS_NOT_CONFIGURED；failed 返回 503/SEARCH_UNAVAILABLE，错误体 code/message/request_id，安全中文说明。partial 保留可用命中及批次错误，不能宣称整批成功。全标点查询虽非空但 tokenize=[] 时正常 200、hits=[]；没有命中不得返回零分占位或编造回答。默认应用不能自动载入示例。

## 3. `/search` 页面

朴素浅色布局：标题“证据搜索”、说明“关键词检索结果，不是自动生成的政策答案”；带 label 的输入框、搜索按钮，Enter 提交；Top 数量本轮固定 5。页面入口链接 `/preview`，README 明确 demo 服务浏览地址。

用户可见：语料状态/有效分块数；按 status 的 parsed_count/synthetic_count 动态提示全合成、部分合成或普通预览，不能把真实资料标作全合成。partial/failed 明确批次错误。结果按 rank 展示标题、正文片段（用实际 chunk.text，完整保留而非生成摘要）、来源站/版本/适用范围/日期、合成标记；“查看原文”跳 `/preview#doc/block`，source_url 仅 http/https。未知范围显示未标注，不推断适用于全体。

每条结果用 `<details>` 提供“匹配依据”：matched_terms、词频和贡献，分数标“关键词匹配分”，不得叫置信度/正确率。显示可四舍五入，API 原分数保留。无需对正文加 HTML 高亮，所有文本使用 textContent 安全 DOM。

空闲、加载中、无匹配、无有效词元、未配置、接口错误区分。输入全空白提示；HTTP/无效 JSON/网络错误可重试原查询，保留输入。不要把错误体当无命中。页面状态与查询请求分别做序号/取消保护，最新提交决定结果，旧成功/旧错误不能覆盖新结果；查询期间用户可以继续输入，重试使用对应失败提交的参数，新的正式提交应更新意图。只因编辑输入不改变已展示结果的“查询：...”标签。

新页面与预览使用同源安全本地链接，无 CDN。桌面和 390px 窄屏能阅读，键盘可提交、可到达链接/展开详情，焦点可见。响应文本/元数据不执行 HTML 或 inline 事件。
