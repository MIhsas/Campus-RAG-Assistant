发布者：Astra。执行者：Claude Code 中的 Mimo。日期：2026-09-21。task_revision=v1。前置：T008-R4 通过。

**目标：** 用可人工核对的来源标注评价 BM25 检索，为后续向量/混合检索提供相同评测输入与可复算结果。

**架构：** 新增离线评测模块，复用 parse_manifest → chunk_documents → BM25Index 的一次性快照。金标准指向原文块中的字符区间，不绑定 chunk_id；指标计算与实际检索分开，后续能替换检索器。Python 标准库及现有 Pydantic 足够，无新服务、数据库、模型或网页。

**方案取舍：** 现在直接接模型会缺少检索效果依据；等待真实语料会暂停工程推进。因此先实现评测工具和小型合成开发夹具。它验证评测流程，不提供论文准确率。真实政策题集在用户给出资料后另行标注，不由模型虚构。

## 1. 问题集契约

UTF-8 JSON，顶层必需 `schema_version="1.0"`、`dataset_id`、`dataset_version`、`split="dev"`、`is_synthetic` 严格布尔、`questions` 非空数组。dataset_id/question_id/evidence_id 均采用现有 ASCII ID 规则严格全串匹配；version 非空字符串。所有结构拒绝未知字段，不隐式转换布尔、数值或字符串。

每题必需：question_id（全数据集唯一）、query（严格字符串 1—500 字符、非全空白，保留原值）、answerable（严格 bool）、evidence（数组）。answerable=true 必须非空，false 必须空。本单不收录参考答案、不做回答正确性评价。每个 evidence 为一个独立必要证据单元，字段：

```json
{
  "evidence_id": "e1",
  "document_id": "syn-parse-txt-001",
  "document_sha256": "填入所标注文件真实的64位SHA256",
  "parser_version": "1.0",
  "block_id": "填入所标注原文块真实ID",
  "char_start": 0,
  "char_end": 10,
  "quote": "填写与这个半开区间完全相同的原文"
}
```

上面展示字段含义；提交的 JSON 必须全为真实夹具值，不保留说明文字。char_start/end 为严格整数、0≤start<end≤len(block.text)，按 Python Unicode 字符、半开区间。quote 必须与原块切片逐字符相同。evidence_id 题内唯一；同题相同 document_id/block_id/start/end 禁止重复，不能重复标一段来改变分母。不同证据单元可位于同一块。

必须先对所有标注核验 document_id、文件 hash、parser_version、block_id、边界与 quote；任一失效则整次失败，不跳过坏题继续算漂亮分数。is_synthetic=false 时拒绝含任何合成文档的语料快照；本单示例必须 true/dev。暂不支持等价替代证据组或测试集冻结操作，README 写明此限制。

## 2. 指标的精确定义

只从 BM25 正分命中中取 Top-K，K 默认 5、严格整数 1—20。一个命中仅能贡献自身 document_id/block_id 下 [char_start,char_end) 区间，其他文档/块的同文内容不能算命中。

对每个金标准证据单元，将同源 Top-K 命中区间与 gold 区间求交，再求区间并集；完整覆盖 gold 区间才计覆盖 1 次。相邻区间可拼合，中间有空隙则不能算完整覆盖；重叠或重复命中不能重复计数。

- **Evidence Recall@K**：覆盖的必要证据单元数 / 该题必要证据单元数。
- **Hit@K**：Top-K 是否存在至少一个与任一 gold 区间有非空交集的结果。
- **MRR@K**：上述第一条相关结果的排名倒数，无交集为 0。
- 注意 Hit/MRR 表示找到相关片段，Recall 表示完整覆盖证据。因此 Hit=1 但 Recall=0 是可能且正确的，不能把它们混为“准确率”。
- 三项仅在 answerable=true 的题上宏平均；分母为可回答题数。没有可回答题时宏指标为 null，不除零、不输出 NaN。
- answerable=false 不参与这三项分母；单独记录返回数量与 `empty_result_rate`（无答案题中零命中比例），无此类题时为 null。它不代表生成式拒答准确率。

每题输出 question_id/query/answerable、按真实顺序的 hit 摘要（rank/score/document_id/block_id/chunk_id/char_start/end/preview_url）、gold_count、covered_evidence_ids、recall/hit/mrr（无答案题为 null）、returned_count。不能给无答案题凭空分配 gold。

手算单元测试基准（不得从被测函数生成期望）：gold=[0,4)、[6,8) 位于同源块；rank1 错误文档，rank2 同源[0,2)，rank3 同源[2,4)，rank4 同源[6,8)。K=2：Recall=0、Hit=1、MRR=1/2；K=3：Recall=1/2、Hit=1、MRR=1/2；K=4：Recall=1、Hit=1、MRR=1/2。重复[0,2)不能补足[2,4)。另测相邻/重叠/间隙、不同文档或块、两个必要证据、无命中、空词元。

## 3. CLI 与结果契约

backend 工作目录命令：

```powershell
& .\.venv\Scripts\python.exe -m campus_assistant.evaluation.run --manifest examples/parse-corpus/manifest.json --corpus-root examples/parse-corpus --questions examples/evaluation/questions.json --top-k 5
```

仅 stdout 输出一个 UTF-8 JSON 对象，不混日志/traceback。成功退出 0；读取、语料、结构或标注错误退出 1；命令用法/非法 top_k 退出 2，参数错误在读取任何文件前检查。默认不写文件，用户可自行重定向。不得在结果暴露机器绝对路径。

成功输出包含 schema_version/evaluator_version="1.0"、valid=true、dataset_id/version/split/is_synthetic、retriever/tokenizer/chunker/parser 版本、参数 max_chars=500/k1=1.5/b=0.75/top_k、question_count/answerable_count/unanswerable_count、summary、per_question、errors=[]。增加实际 manifest/questions 原始字节 SHA-256 与 corpus 文档 ID/hash 清单，便于识别使用的数据；不生成随机时间戳作为确定性内容。

失败输出 valid=false、errors（code/question_id/evidence_id 可空、field、安全中文 message）、summary=null、per_question=[]。可包含已确认的数据集身份和计数，未知用 null；不得保留部分成绩让失败看似有效。稳定错误码至少区分 DATASET_READ_ERROR、DATASET_SCHEMA_ERROR、CORPUS_ERROR、EVIDENCE_REFERENCE_ERROR。上游 partial/failed 都属于本次评测失败，报告安全错误，不能偷偷只评成功文件。

实际 parse_manifest 一次、chunk_documents 一次、BM25Index 一次，多道题复用索引，不循环调用现有单题 CLI 的 _run_search。语料解析后先完成题集结构/来源校验，失败不得检索；纯参数失败更不得解析。测试在真实函数边界计数。
