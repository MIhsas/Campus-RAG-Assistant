## 数据加载与状态

应用工厂增加可选关键字参数 manifest_path/corpus_root，两者必须同时提供，否则在创建时明确报配置错误。默认都不提供，不自动扫描磁盘，也不默认加载测试资料。仅在创建应用时调用已有 parse_manifest 一次，结果快照保存在各自 app.state；接口读取快照，不在每次请求中重解析。不同 app 实例不得串数据。

另提供专用演示入口模块（如 campus_assistant.demo:app），只加载仓库内 examples/parse-corpus 合成示例，README 给出独立 uvicorn 启动命令。任意客户端请求不得指定本机路径，未提供下载接口。更换语料后通过重启重新加载，本阶段不做热更新。

支持四种状态：unconfigured（未配置）、ready（整批成功）、partial（有失败但有成功文档）、failed（无可展示成功文档且校验或解析失败）。状态命名在接口和页面统一。预览 ready 仅代表正文快照可浏览；既有 `/api/v1/health/ready` 继续返回知识问答未就绪 503。

## API 契约

- GET `/api/v1/corpus/status`：始终 200，返回 status、document_count（沿用解析器结构合法登记数）、parsed_count（可展示文档数）、errors、request_id。未配置时计数 0；错误信息中文且不暴露本机绝对路径。
- GET `/api/v1/corpus/documents`：未配置 503/CORPUS_NOT_CONFIGURED；已加载（含 partial/failed）200，返回 items 数组和 request_id。每项 document_id、title、source_site、source_url、version_label、is_synthetic、block_count、warnings。失败文档不冒充成功记录。
- GET `/api/v1/corpus/documents/{document_id}`：未配置 503；已加载但未知 ID 为 404/DOCUMENT_NOT_FOUND；成功 200，返回 document（含 metadata、parser_version、blocks、warnings）及 request_id。

新接口使用明确的 Pydantic 响应结构，并在 OpenAPI 声明预期错误码；复用已有 request.state.request_id，与 X-Request-ID 一致。不要重写健康接口。errors 可沿用已验证的错误结构；不用新增全局异常框架。

## 页面 /preview

使用 backend 包内静态 HTML/CSS/JS，由 FastAPI 返回；注意打包配置包含资源，不能依赖启动 cwd。无需框架/CDN/字体下载。所有内容均由上述 API 获取，禁止在前端硬编码成功文档。

布局：桌面左侧文档列表和标题筛选，右侧详情；窄屏上下排列。用清晰中文标签和朴素浅色样式，重点是可读性与定位，不做装饰性仪表盘。

必须可见的行为：

1. 页面标题“语料预览”；合成资料展示“合成测试，不代表学校政策”，真实与合成区分由 is_synthetic 决定，不全局伪造真实语料。
2. 列表展示标题、格式（从 metadata 可得时）、块数和警告标记；客户端按标题筛选，明确这不是全文检索或 RAG。
3. 详情展示来源站、可点击 source_url、版本、三个日期、适用范围；null 日期和空范围分别显示“未标注”，不显示“适用于全部”。来源链接仅允许 http/https，新标签页用适当 rel，不执行源文档中其他链接。
4. 按原顺序展示正文；段落保留换行；表格行使用 cells 清晰展示列（简单表格即可）。每块显示 locator 的人类可读位置，不把 DOCX 段落号伪装为页码。
5. 支持跳转到块：页面 URL 使用 document_id/block_id 参数或 hash；复制定位链接后刷新，仍选中对应文档并滚动高亮目标块。不存在 ID/块给出提示，不静默显示错误文档。剪贴板不可用时提供可选择的链接文本。
6. 文档 warnings 可见，partial/failed 时页面展示批次错误，不能只显示成功文档而隐藏导入失败。未配置、加载中、无匹配项、API 失败均有明确状态；允许重试读取快照。

正文和元数据均作为不可信文本呈现：使用 textContent/安全 DOM API，不以 innerHTML 执行正文。保持基本键盘操作、label 和焦点可见。不给 /preview 增加假问答输入框、登录或上传按钮。
