# T015 问答页体验与本机历史

日期：2026-09-27；task_revision=v1。Astra 发布，MiMo v2.6 Pro 执行。前置：T014 已通过，见 T014-R3。

## 目标与范围

把已有问答能力串成适合答辩操作的页面流程：提问、生成或查看摘录、定位引用与原文、失败后查看依据、保存并恢复本机问答记录。复用现有 ask.html 和 API；不重建前端框架、不引入数据库、Agent、语音或新的检索算法。

允许修改 step2_code/backend 中 ask 页面、直接相关脚本/测试及 README/env.example 的必要说明，以及 submissions/T015/。若发现必须调整 API，先说明具体原因和兼容性；不以本任务重构已验收后端。不得修改 Astra 文档、旧题集/gold 或 T014 原始证据。

## 功能交付

1. 问答模式表达清楚。保留“整理依据”和“生成答案”，说明两者区别；生成器未配置时仍可用摘录。清理仅适用于早期离线阶段的过时文案。生成过程显示等待状态并防止重复提交；不自动生成、自动重试或因状态刷新再次调用。保留 query/mode/filters/answer_mode 的提交快照及 T011-R1 筛选保留规则。
2. 引用交互。生成段落的 E 编号可定位到当前证据卡并高亮，卡片可打开对应原文；展现资料标题、适用范围及可用日期信息，不把资料准入当资格认证。复制内容包含答案或摘录、编号与来源。已有可用功能直接复用，不重复实现。
3. 生成失败后提供“查看本次问题的原文依据”，使用失败请求的查询和筛选快照发送 extractive 请求，不能悄悄改为无筛选、不能重新调用模型。明确区分生成失败、材料不足、纯摘录三种结果。
4. 本机历史：仅在用户开启“在本机保存历史”后持久化到 localStorage，默认关闭；页面明确仅保存在此浏览器、不是学校账户记录。最多 20 条，新的替换最旧的。记录成功的 generated/evidence_only/insufficient_evidence 结果及时间、提交快照和来源；不保存密钥或原始异常。列表可重新查看、删除单条、清空；重新查看不得发模型请求。历史结果标注保存时间及“历史结果，资料可能已更新”；用户明确再次提问才发新请求。关闭保存时说明保留记录状态，并提供清空操作。存储不可用时提示且不影响当前问答。暂不做云同步、导出或复杂迁移。
5. Windows 运行说明：补充当前已验证的 DeepSeek 环境配置及可选 NO_PROXY=api.deepseek.com（仅当前进程，针对代理路径 TLS 失败）。不修改系统代理或全局环境，不要求另建代理配置模块；密钥不进文档或页面。

## 验证与边界

- 只做相关 JS 语法、现有必要行为回归及新增主流程验证；无后端变更不重跑全量 pytest、embedding 或评测。
- 用隔离的本地测试 fixture/mock 验证生成结果、引用定位、错误转摘录、历史恢复不调用模型、保存开关与删除。模拟回答必须有明显标记，不能作为真实 DeepSeek 证据；fake 不进入产品启动路径。
- 有浏览器工具则完成一次“提问→模拟生成→引用/原文→复制→历史恢复”及错误转摘录验证。无浏览器工具时如实交付可供 Astra 运行的本地演示入口和步骤，不自行安装大型浏览器工具；stub 不冒充真实浏览器证据。
- 本任务只授权本地开发和本地模拟，不授权任何新的外部模型请求，也不允许为了页面演示重放 T014 付费调用。
- 不新增冗余安全矩阵或边界测试；主流程正确性、结果快照和调用次数是验收重点。
