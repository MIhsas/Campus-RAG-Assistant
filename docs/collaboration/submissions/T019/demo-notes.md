## 四个可操作场景（5 分钟内可演示）

| 场景 | 操作 | 预期 |
|---|---|---|
| a 全满足 | 四项全选“是”→ 手动自查 | 绿色横幅“按自填信息满足本演示列出的条件；仍需学校审核，不构成录取、批准或申请成功”；四项均“满足” |
| b 缺考核信息 | 第 4 项选“不确定 / 未填写”（含未参加考核）→ 自查 | 橙色“仍有待核实项”；第 4 项“待核实”（与“否/不满足”明确区分） |
| c 一个不满足 | 第 2 项选“否”→ 自查 | 红色“存在未满足项”；第 2 项“不满足” |
| d 依据被筛除 | 入学年份填 2022（下拉可选） → 自查 | 粉色“依据不足，无法完成自查”；各项“依据不可用”、引用区“不作为自查依据”；**与 c 的个人不满足明确区分** |

## Astra 逐步检查表（页面闭环）

| 检查 | 步骤 | 预期 |
|---|---|---|
| a 表单 | 进入 /self-check | 四项三态下拉（是/否/不确定或未填写），载明规则版本与“不收集：姓名、学号、违纪详情” |
| b 结果快照 | 选填并自查 | 快照行显示“已提交输入 + 条件”；逐项含已填答案、状态标签、解释与原文引用（quote + 查看原文跳转） |
| c 改表单不改旧结果 | 出结果后再改下拉 | 结果区不变；再次“手动自查”才出新结果 |
| d 失败不冒充 | 断开服务后自查 | 明示“未生成新结果”，旧结果不冒充新比较 |
| e 清空表单 | 点“清空表单” | 下拉复位；已有结果与快照保持 |
| f 隐私 | 全程 Network/存储 | 仅 rule/eval 请求；无 localStorage 写入；请求体仅 filters+四项三态 |

## 边界说明

- 合成规则（rule_version 1.0）绑定 parse-corpus 第五条；**确定性规则，无模型、无 eval**；不代表学校审核/资格结论。
- 规则由工厂显式注入（demo-campus）；普通服务未配置时接口 503、页面提示“自查规则未配置”。
- 填报仅在请求内处理；不写报告/日志/localStorage。
