### R3：异常输入破坏 CLI JSON 契约（P1）

位置：corpus/validate.py:173 及清单读取、路径解析异常处理；Scope 的 before 验证器。

- scope.campus=null 时，before 验证器抛 TypeError，`except Exception` 随后错误调用 e.errors()，产生 AttributeError。CLI 退出 1，但 stdout 不是 JSON，stderr 出现堆栈。
- 非 UTF-8 清单字节 0xff 导致 UnicodeDecodeError，未转换为规定错误结果。

只对实际 Pydantic ValidationError 读取 errors；通过正确的模型类型校验处理坏输入。编码错误映射 MANIFEST_READ_ERROR；路径解析、文件状态检查和读取的预期异常也应转换为稳定错误对象，不能把原始 OSError 文本中的机器绝对路径输出给用户。不要用一个吞掉所有程序错误的 broad except 冒充正确处理。错误 message 按任务使用中文，不直接转发英文 Pydantic 消息。增加 subprocess 测试验证退出码 1、stdout 可解析且无绝对路径、无异常堆栈。

### R4：document_count 与错误收集契约不符（P2）

位置：corpus/validate.py:207、215、265；TestMultipleErrors。

document_count 约定是“通过结构验证的输入条目数”，当前实现却统计文件检查成功数。合法双文档清单仅改坏一个哈希，实际 count=1，应该为 2；三个结构合法条目的测试期望应为 3，不能用现有测试的期望覆盖任务要求。

重复 ID 与坏哈希并存时，当前提前返回只报重复 ID、count=0。结构验证成功后保留条目数，并继续收集能安全执行的逐文件错误。结构验证失败时 count=0。同步 README、测试和 verification 中的描述。
