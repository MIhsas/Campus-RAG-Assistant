## 必须修复：按意见筛选不应使用正文短编号猜归属

位置：`scripts/human-review-pack.html` 的 `applyFilter()`，约237—240行。

当前代码遍历全局state，并用 `k.split('/').slice(-1)[0]` 是否出现在卡片正文中判断归属。证据ID如 `f1-s1` 在多题中重复；模板引用的跨度数字更不唯一。于是某条意见可以错误地让其他未复核卡片通过筛选。

Astra独立因果链（`T036-filter-probe.cjs`，DOM桩，非浏览器）：

1. 默认包114项全部未复核；
2. 仅通过q01首条证据的选择器change事件设为“需修订”；
3. 顶部按“需修订”筛选；
4. 预期仅q01卡片，实际显示q01—q20全部20道可答题；探针exit 1，见 `T036-filter-probe.json`。

独立探针补齐了真实DOM中textContent包含子节点文字的语义；原行为桩没有调用意见筛选，且textContent不含子节点，因此漏掉此问题。不是证据导出数据被改，但复核页面筛选会错误展示归属，须修复。

修复方案任选简单实现：为每个意见行绑定完整state key，再从当前卡片实际拥有的意见行取状态；或直接读该卡片内部意见select的当前值。不扫描全局state的短ID/正文/跨度数字。题目本身、证据、步骤、引用均遵循“本卡片任一意见匹配才展示”。空筛选=全部；文字与意见条件求交。修改意见时同步更新当前筛选，避免残留旧显示。模板摘要卡没有意见，允许仅作为上下文展示，不能据此计入匹配步骤。

新增最少因果链回归：q01/f1-s1需修订→仅q01；另一题的同名f1-s1仍未复核且不显示；切回未复核/全部符合本卡片状态；模板选一条引用同样不误带其他步骤。默认与单项导出原15项保持。无需扩展全量矩阵。
