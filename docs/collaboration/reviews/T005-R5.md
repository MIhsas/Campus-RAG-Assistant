## R1：列表恢复后丢失待定位目标（P2）

本问题属于已有“错误恢复时保留 document_id/block_id、深链接回归”要求，不新增功能。

使用本轮只读产品、仅注入合成响应的测试服务器 `T005-R5-server.py`。从新启动的服务器打开：

`/preview?scenario=list-once#syn-parse-docx-001/e57ac232ebc1c1a5`

1. 列表首次返回 HTTP 500，状态接口成功。右侧却显示“语料未配置或无文档”。
2. 输入“课程”，点击列表“重试”。列表成功恢复，显示唯一匹配 DOCX。
3. URL 仍保留完整 document_id/block_id，但右侧仍为“语料未配置或无文档”，没有选中文档、正文或块高亮。

根因：loadDocs 的失败分支设置 docsLoaded=true；初始化 `.then(handleHash)` 随后把空 allDocs 当未配置/无文档，没有保留 pendingDocId/pendingBlockId。成功重试仅 processPending，已没有待处理目标，因此恢复链断开。相关位置：preview.html 的 loadDocs、handleHash（约 489 行）、processPending（约 523 行）、初始化（约 544 行）。

限定修复：

- 将“请求已结束”和“成功得到列表”分开判断；暂时失败不能推断为无语料或未知文档。
- 保留当前 URL 的待定位意图，列表成功后自动恢复目标文档及块高亮，保持当前筛选；不要求用户手动刷新或重新点文档。
- 恢复时只执行最新定位意图，避免旧 pending 覆盖用户期间新选择；未知 ID/块仍明确提示，真正未配置/空列表保留正确提示。
- 不重写已通过的请求序号、错误明细管理和详情重试。
