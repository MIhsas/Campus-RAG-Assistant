## R1：损坏 DOCX 的 XML 异常逃出文档隔离边界（P1）

位置：`step2_code/backend/src/campus_assistant/corpus/parse.py:273` 的正文迭代异常捕获。

真实复现：用 python-docx 创建一个普通一格表格，在单元格 tcPr 加入缺失必需 `w:val` 的 `<w:gridSpan/>`，保存为 DOCX；与一个正常 TXT 放入同一清单，按实际内容填写 SHA-256。清单及文件完整性校验通过，但遍历 `row.cells` 时抛出 `docx.oxml.exceptions.InvalidXmlError`。它不属于当前捕获的 ValueError/TypeError/KeyError/AttributeError/ET.ParseError。

实测 `parse_manifest` 与 `create_app` 均直接抛出 InvalidXmlError；解析 CLI 退出 1、stdout 为空、stderr 有 Traceback。结果是一个坏 DOCX 让整个配置应用无法创建，正常 TXT 无法保留为 partial，违反 T004 的文档级隔离与 JSON 输出约定。这不是要求恢复复杂表格内容，而是要求明确失败且不拖垮其他文件。

修复要求：在真正的单文档 DOCX 解析边界处理已知第三方 XML/格式异常，返回安全中文 DOCUMENT_PARSE_ERROR，保留正常文档。不要在 main/create_app 最外层把所有错误改称清单错误，也不要返回已经提取一半的伪成功文档。无需升级依赖或扩展格式支持。

测试必须使用实际保存的坏 DOCX（上面探针可复用构造方法），不能仅 monkeypatch 抛 ValueError：

- 正常 TXT + 坏 DOCX，两种顺序：valid=false、保留正常文档、错误关联坏文档；CLI 单一 UTF-8 JSON，退出 1，无 traceback。
- 对应工厂可创建，corpus/search 状态 partial，正常证据可查询，preview/live 可访问。
- 仅坏 DOCX：工厂可创建，状态 failed，搜索 503，live 200，知识问答 ready 503。

## R2：空白提交遗留禁用按钮（P2）

位置：`step2_code/backend/src/campus_assistant/static/search.html:185` 的空白分支。

本轮浏览器使用既有 T008-R2-server.py，POST 延迟 12 秒：搜索“缓考申请”→立即清空输入并 Enter→显示“请输入搜索关键词”、搜索按钮 disabled。超过 12 秒并确认旧请求结束后，填写“学籍”，按钮仍 disabled，鼠标无法再次搜索。再次用 Enter 提交有效查询后才恢复。

revision 3 正确地使旧请求失效，并保护旧完成回调不改按钮；但新的本地校验失败分支没有结束当前加载状态，导致无人恢复按钮。旧结果覆盖提示的问题已关闭，按钮生命周期问题仍未关闭。

修复要求：空白提交更新意图后必须恢复当前可提交状态，不发送空查询。统一明确有效提交、本地拒绝、成功、失败、重试、过期完成这几种状态转换，避免继续仅逐行补序号。保留草稿与提交参数区分以及旧请求守卫。

补可执行的异步行为回归：A 延迟→空白 Enter，提示保留且按钮立即可用；A 成功或失败晚到均不影响当前提示/按钮；随后输入 B 可直接点击按钮搜索；A→B 时 A 完成不能提前释放 B；失败后编辑草稿再重试仍查询原参数。断言应针对结果、按钮和请求参数，不接受源码包含字符串作为行为证据。不为此安装新依赖；无浏览器能力如实注明，由 Astra 补验。

## R3：登记 ID 错误接受末尾换行（P2）

位置：`step2_code/backend/src/campus_assistant/corpus/models.py:84`。

`_ID_PATTERN` 用 `$` 结尾再调用 match，Python 的 `$` 可匹配最终换行之前。实际 document_id=`good\n` 被校验为 valid=true，进入正文/分块/检索；生成 `/preview#good%0A/...`，详情 API 也接受该 ID。它与可见文本近似的 `good` 成为不同登记键，违反 T003 明确的 ASCII ID 契约，并影响后续版本分组和来源标识。policy_group_id 复用同一验证器。

修复要求：两个 ID 字段采用整个字符串严格匹配，拒绝换行等额外字符；不通过 strip 静默改写 ID。添加正常 1/64 位及非法 65 位、尾换行/CRLF、内部换行、首尾空白的验证测试，并确认 document_id 与 policy_group_id 均覆盖。非法清单返回 MANIFEST_SCHEMA_ERROR，不进入解析。
