## P1-2：失效 document_id 被转换成全库检索

位置：两页 `currentDocumentId()`、`loadSourceCatalog()` 和 `initParams.document_id` 恢复逻辑；ask 初始化约 1190—1204 行。

真实浏览器直接打开：`/ask?query=申请转专业&document_id=unavailable-review-file`。

- 页面模式仍为「指定文件」，文件控件为空，提示 `未选择指定文件：检索范围为全部资料。`
- 点击「整理依据」，结果快照为 `来源：全部资料`，返回 5 条证据。

原因：两次向原生 select 写入不存在的 ID 都得到空值，随后 currentDocumentId 把空值转为 null。已有 ghost-option 逻辑只看控件 prev，无法恢复已丢失的 URL 原值。后端对未知 ID 的 422 因前端未发送原 ID 而被绕开。

要求：保存原始待恢复 ID，失效 ID 保留为明确不可用选择并提示，或阻止提交要求用户重新选择；也可保留原 ID 让服务端明确 422，但绝不能转 null 执行全库检索。只有用户显式选择「全部资料」才撤销已有指定条件。目录加载失败时同样不能把待恢复 ID 静默取消。指定文件模式未选文件应提示完成选择或显式切回全部资料。
