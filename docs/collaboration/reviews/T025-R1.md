## 1. P1：mock 的 loopback 限定可被前缀绕过

`live-smoke-planner.py` 的 host_ok 使用 startswith。`http://127.0.0.1.example.invalid` 和 `http://localhost@example.invalid` 都通过前置检查，实际主机却不是本地；随后脚本会向该目标发送合成问题及观察。这破坏 A 阶段“仅本地 mock、零外部调用”的边界。

用标准 URL 解析校验 scheme、完整 hostname，限定明确的 localhost/127.0.0.1（如支持 ::1 则准确解析），拒绝 userinfo、畸形端口等；不要靠前缀，不进行 DNS 探测。拒绝时保持零发送、非零退出。只需正常 loopback + 上述两例回归，不扩展安全矩阵。

## 2. P2：已获取的失败轮审计被丢弃

`agent/deepseek_planner.py` 在解析响应后构建 audit，但 length/空内容/非法动作等异常直接抛出；workflow 的 plan_error 固定 audit=None。报告“失败轮保留”不成立。真实请求被截断也可能已计费，不能把已返回字段当成未提供。

以最小异常元数据或等效机制保留允许的审计字段并进入最终运行记录：id/model/usage/finish_reason/latency/max_tokens；不得传播 headers、密钥、原始响应正文。未收到字段仍为 null。用带审计的 length 响应覆盖实际脚本输出；保留一次请求、exit 1、无重试。无需重构问答 provider。
