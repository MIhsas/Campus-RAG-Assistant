## A：日期字段的必需性和格式仍不符合契约

位置：`corpus/models.py` 的 published_at/effective_from/effective_to 定义与 validate_date。

实际复现：删除全部三个日期字段，仍 valid=true / exit 0；published_at="20240901" 或 "2024-W36-7" 也 valid=true / exit 0。

原因：字段仍有 `= None` 默认值；Python 3.12 的 date.fromisoformat 同时支持紧凑格式和周日期，单独调用不能保证任务要求的 YYYY-MM-DD。混用这些格式还会使当前字符串起止比较失去可靠性。

必须修复：三个字段均必需但允许显式 null；严格匹配 ASCII YYYY-MM-DD 形状后验证真实日历日期，或采用等效严格实现。日期起止比较使用解析后日期或已保证统一格式的值。补充三个字段各自遗漏、显式 null、紧凑格式、周日期的测试，保留已通过的非法月份/闰年/倒置日期测试。

## B：非法文件路径仍会破坏 CLI 输出

位置：`corpus/validate.py` 的路径安全、resolve、文件状态检查。

实际复现：将合法示例的一项 local_path 改为 JSON 字符串 `"bad\u0000name.txt"`，CLI 退出 1，但 stdout 不是 JSON，stderr 最后一行为 `ValueError: stat: embedded null character in path`。

必须修复：在任何文件系统操作前拒绝 NUL 路径，返回 UNSAFE_LOCAL_PATH；将根目录与目标路径解析、文件状态检查中预期的输入/文件系统异常转为约定 JSON 错误，保留逐文件错误收集。不要遗漏 main 中预先 resolve 的入口。不输出机器绝对路径或堆栈，也不使用吞掉全部编程错误的兜底替代明确处理。增加真实 subprocess 回归用例，断言合法 JSON、退出码 1、稳定错误码及无 Traceback。
