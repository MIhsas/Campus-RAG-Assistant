## 2. 必修一：冻结校验实际为空操作（P1）

`scripts/check-real-eval.py` 使用 `fz.get("files", [])`，真实 freeze 没有顶层 `files`，只有 `dataset`、`corpus_pack`、`implementation_sha256`、`embedding_model` 等。因此任何这类 freeze 都跳过哈希检查。

修复要求：

1. 按本项目实际 schema 校验题集、manifest、语料文件、实现文件、模型身份文件；路径基准明确，不依赖调用者碰巧位于某个目录。缺少必需节/空清单/不支持结构应明确失败，不能“检查了零项却成功”。
2. 记录实际检查数量；哈希错误、缺文件非零退出。校验只读，不修补输入。
3. 随单补入原任务要求的标注说明文件哈希。**旧 freeze 原样归档，不追溯伪装成旧版本已经冻结过该文件。** 新数据修订冻结标注后再重检索。
4. 只需聚焦回归：有效实际结构通过、错误题集哈希拒绝、缺关键结构拒绝；其他文件类别用一个小型参数化哈希漂移检查覆盖即可，不扩展安全矩阵。复跑 Astra 错哈希探针，返回值必须符合期望。

## 4. 必修三：题目范围与标准答案不一致（P1）

以下是完整原文已确认的具体情况，请在同一次标注复核中解决：

- **q01/q02** 泛问缓考/补考最高成绩，但 gold 仅列85/75。bb8ba97c 的 `9de19468b7427552`（第23页）明确区分初修85/75与重修65/60。若目标就是85/75，应把“初修”写进题面及事实定义，不将该结论泛化为全部课程；指定来源/版本范围需显式且有语义理由。
- **q06 与配对 u04** 问“学籍信息核对可以到哪里办理”，引用 `f74aff0841628203` 实际规定的是**基本信息有误，由学生本人提交申请及证明材料办理更正**；普通信息核查在学信档案中进行。把问题改成与原文一致的更正场景，两道同题筛选对同步改，仍须如实保留本科筛选排除未知 scope 的产品语义。
- **q11** 泛问教发〔2018〕10号缓考、补考、再修如何记载，f3只包含“不合格课程再修≤65”。同文 `43602ebd8cb36c00` 紧接规定“已合格课程再修成绩以实际最高分记为有效成绩”。要么明确问三个特定情形/最高分规则，要么完整标注问题所问范围；不能用当前三档代表全部再修规则。
- **q12** 问申请转专业必须符合哪些条件，gold只覆盖“二（一）”三条；同页“二（二）”还有四类不能申请情形。建议明确问“二（一）列出的三项基本申请条件”，避免将三个正面条件包装成全部资格判定。
- **q15 及其版本对照 q14** 请明确比较的是申请条件条款中的课程要求。2026版第1—2页另有跨校区超额时按必修课初修成绩专业排名百分比排序；不得把“取消前40%固定申请门槛”写成“任何场景均无排名要求”。如题面改变，对照两题同步明确范围。

以上可通过明确问题语义或补全事实解决，不要求新增政策推理引擎；不要为保住旧得分选择措辞。q10 等条件分支也随全题复核确认：原文中的“开展学生互评时”等前提不能在完整事实定义中消失。
