renderDetail 用 el.innerHTML 替换详情区后，再通过 getElementById('detail-empty').style 访问已被删除的旧节点，抛出异常；selectDoc 的 catch 随即用“加载失败”覆盖成功渲染的正文。浏览器复现的详情 HTTP 请求实际返回 200，因此不是 API 或语料问题。

## R2：块定位链接无法可靠保留与恢复（P1）

位置：selectDoc、updateHash、handleHash。

handleHash 读取 document_id/block_id 后调用 selectDoc，后者立即 updateHash(docId) 丢掉 block_id；修复 R1 后也会导致下一次刷新失去目标位置。未知 block_id 没有任何提示。allDocs.length===0 的递归计时器无法区分“尚在加载”与“未配置/失败/确实无文档”，会无限等待。

以明确加载完成状态处理定位；传递并保留 block_id，不靠固定 100ms 延时和无限轮询。分别处理未知文档、未知块、坏 URI 编码和未配置；切换文档时防止较慢的旧请求覆盖新选择。验证复制链接、重新打开、再次刷新仍能高亮并定位同一块，以及不存在目标时的提示。

## R4：使用安全 DOM API，避免属性上下文注入（P1）

位置：esc、renderDetail 的来源链接拼接以及其他 innerHTML 渲染。

当前 esc 通过 div.textContent 再取 innerHTML，只适合文本上下文，不保证转义属性中的双引号；把 esc(safeUrl) 拼入带引号的 href 仍可破坏属性边界。现有 source_url 校验只检查协议/主机/凭据，不能作为 HTML 属性转义。此项是源码确认的风险，不声称本轮已在浏览器执行攻击。

按原任务用 createElement、textContent、经过协议检查的 href 属性赋值和 addEventListener，移除将语料数据拼接成 HTML 或内联 onclick 的路径。正文、标题、来源及其他元数据都视为不可信输入。增加带引号/标签/事件样式文本的合成用例，浏览器确认它们仅显示为文本、不产生额外元素或事件属性；来源只允许 http/https 且保留 noopener noreferrer。
