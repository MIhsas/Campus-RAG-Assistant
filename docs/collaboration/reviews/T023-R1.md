## 必修项

### 1. P1：模拟规划器进度跨请求共享，第二次运行空完成

`agent/planner.py:58-64` 的 `_i` 在实例内累加，而 `main.py:110` 把同一实例放入 app state，API 每次复用。相同页面连续两次点击模拟规划：第一次执行 search_policy、build_checklist_draft；第二次显示“工具调用：0 次；规划轮次：1 / 4”“脚本动作已全部执行完毕”，结果消失。

修复为每次运行独立状态，或无状态脚本按本轮 round_no 取动作；不要靠重启服务、页面刷新或共享实例 reset（会再次共享运行状态）解决。回归用同一个 app/client 连续两次请求，第二次换事项或条件，确保工具照常执行且结果属于第二次快照。

### 2. P1：非空无效年份被静默转换为不限

`static/workflow.html:124` 用 parseInt，`abc` 得到 NaN，经 JSON.stringify 变为 null。实测：先运行 2023，再把年份改成 abc 后运行，页面仍报告成功，草稿出现“需医院证明”，办理链接 admission_year 为空。条件确实被放宽，不是仅错误提示不友好。

复用现有筛选选择或严格验证完整输入；非空非法年份应提示并停止提交，不可变成 null，也不可把部分字符串截成合法年份。保留留空=不限。覆盖合法 2023、空白、abc/2023abc 三类即可，不扩展边界矩阵。

### 3. P2：失败后旧依据、旧草稿及办理链接仍作为当前内容展示

`static/workflow.html:279-306`：成功运行后填日期 bad-date，再运行收到 HTTP 422；仅步骤区变为失败，旧 evidence-panel/draft-panel 与可点击办理链接仍保留，且没有旧结果快照/失效标识。

新请求开始时使旧结果操作失效；失败时隐藏旧结果和办理入口，明确“本次未生成新结果”。若保留历史展示必须显式标旧快照并禁用当前结果操作，优先采用简单清空方案。成功结果展示提交时条件快照，不能只依赖会变化的输入框。覆盖成功→422，以及网络异常共用清理逻辑；无需搭复杂网络故障平台。
