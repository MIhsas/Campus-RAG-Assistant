## R1：旧响应覆盖当前文档（P1）

原返工单已要求防止旧请求覆盖新选择，本次 selectDoc 仍未做请求版本或取消处理。

独立测试服务器只给 TXT 详情增加 10 秒延迟，其他应用逻辑未修改。先选 TXT，立即选 DOCX，DOCX 先正常显示；TXT 响应随后到达，覆盖了右侧详情。最终真实 DOM：

```json
{"hash":"#syn-parse-docx-001","detailId":"syn-parse-txt-001","selected":"合成测试课程成绩登记表（正文解析示例）DOCX · 11 块 · 合成"}
```

已查看截图确认左侧选中 DOCX、右侧却显示 TXT。该问题会使来源、正文和用户所选文档不一致，不能进入检索阶段。

修复：为每次详情选择建立请求序号/取消机制，只有最新请求可写入成功、错误或加载状态；使用本次请求自己的 document_id/block_id，不依赖可能已被后续选择改写的全局变量。快速同文档不同块跳转、旧请求失败晚到也不能覆盖新状态。不得简单禁止全部交互来掩盖问题。

## R2：HTTP 错误被伪装为空列表（P2）

fetch 对 HTTP 500 不会自动抛异常；loadDocs 只单独判断 503，随后把 JSON 错误体当列表并执行 `d.items || []`。独立注入列表接口 HTTP 500 + JSON 错误体，浏览器实际显示“状态：就绪 文档：2/2”“暂无文档”，且无重试按钮。

修复：status/list/detail 三类 fetch 均检查 HTTP 状态，区分预期 503/404、真正空数据、其他 HTTP 错误、JSON 解析失败与网络中断；错误时给出明确提示和可操作重试，不把错误体作为成功数据。重试统一刷新必要的状态和列表，保留当前筛选，避免旧请求/旧错误覆盖新状态。loadStatus 重复插入的错误明细应替换而非累加，旧明细恢复成功后应清除。
