## R1：输出对象未独立隔离（P1）

chunk_documents 每份文档只 deepcopy 一次 metadata，所有 chunk 指向同一个 metadata_copy；locator 直接引用输入 block 的 dict。

实际将第一个 chunk 的 metadata.scope.campus 追加“合成校区”，第二个 chunk 随之变化。将第一个 chunk 的 locator.line_start 改为 99，输入原文 block 的 locator 也变为 99。后续检索增强或引用处理若修改某条结果，会污染其他候选甚至原始解析快照，违背纯函数输出隔离要求。

限定修复：每个 chunk 的 metadata、locator 及其嵌套容器应与输入及其他 chunk 独立；检查 cells/warnings 同样遵守原任务约定。测试至少两个同源 chunk，分别修改输出 metadata/locator，验证输入、兄弟 chunk 不变。现有 metadata 测试只产生单个 chunk，无法覆盖兄弟共享问题。

## R2：CLI 越界参数错误码不正确（P2）

真实 CLI `--max-chars 0` 与 `--max-chars 10001` 均退出 1，stdout 输出 valid=false JSON，并对两份文档各生成一条 CHUNK_ERROR。原任务要求参数错误退出 2，不输出伪造成功 JSON；配置错误也不应被记录成逐文档失败。

限定修复：CLI 参数解析阶段统一验证整数范围，先于路径解析和 parse_manifest 执行，使用 argparse 的错误语义（stderr 说明、退出 2、stdout 空）。纯函数仍严格拒绝 bool/float/string/越界。chunk_manifest 作为新增公共入口也应在解析语料前检查 max_chars，避免无文档时绕过验证、不同文档数产生不一致行为。

补真实子进程测试 0、-1、10001、非整数，以及有效边界 1/10000；无效参数在空/不存在 manifest 时同样优先返回参数错误，且 parse_manifest 不被调用。区分参数错误、解析错误和分块内部异常，不把所有情况塞入同一 catch。

## R3：未按 block.ordinal 排序（P2）

任务约定按文档输入顺序、block.ordinal、片段顺序输出。实现直接遍历 blocks 数组。独立输入数组先放 ordinal=2 文本“后”，再放 ordinal=1 文本“前”，实际输出为“后、前”。现有 ordering 测试输入本来已排序，无法捕获此问题。

限定修复：在不改变输入数组的前提下按 ordinal 遍历；仍保持文档输入顺序及每个文档的 chunk.ordinal 从 1 连续。增加乱序 blocks 混合段落/表格测试，验证原输入不变、区间及 ID 不失真。无需重构解析器或添加新排序策略。
